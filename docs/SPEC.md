# To-do behavior and HTTP contract

Status: implementation contract; framework choice remains pending.

## Resource

```json
{
  "id": "server-generated UUID",
  "title": "Prepare interview notes",
  "description": null,
  "dueDate": "2026-10-15",
  "isCompleted": false,
  "createdAt": "2026-10-10T14:00:00Z"
}
```

Title is trimmed and must contain 1–200 characters. Description is nullable and
limited to 5,000 characters. Due date is nullable and must be exactly YYYY-MM-DD
and a real calendar date. Completion is a strict boolean. ID and createdAt are
immutable and generated by the server. Unknown request fields are rejected.

## Routes

| Method | Path | Behavior | Success |
| --- | --- | --- | --- |
| POST | /api/todos | Create from title, optional description/dueDate/isCompleted | 201 + resource |
| GET | /api/todos | Filtered/sorted list; empty result is [] | 200 |
| GET | /api/todos/{id} | Read full resource | 200 |
| PATCH | /api/todos/{id} | Update supplied mutable fields | 200 + resource |
| DELETE | /api/todos/{id} | Delete resource | 204, no body |
| GET | /api/health | Application health | 200 |

Creation returns a Location header pointing to the new resource. PATCH can set
isCompleted true or false; repeated assignments succeed without changing
createdAt. Omitted fields are preserved. Null clears description/dueDate but is
invalid for title/isCompleted. Empty PATCH is a valid no-op for an existing task.

Malformed IDs and inputs return 422; valid IDs that do not exist return 404,
including repeated deletion. Errors use JSON with a detail field; validation
errors identify the affected field. No internal database details reach clients.

## Query semantics

GET /api/todos accepts status=all|incomplete|completed|overdue (default all),
sort=createdAt|dueDate|title (default createdAt), and order=asc|desc (default desc).
Filters compose with sorting. Unknown enum values return 422.

Overdue tasks are incomplete with dueDate strictly before the current UTC date.
Tasks due today, completed tasks, and undated tasks are not overdue. Title sorting
is case insensitive. Missing due dates always sort last in either direction.
All sorts use ascending ID as a deterministic final tie-breaker. Calendar dates
are displayed without conversion to local timestamp offsets.

## Acceptance scenarios

1. Create a task with only a title: default status is incomplete, optional fields
   are null, generated identity and timestamp are returned, and it appears in list.
2. Read and edit a task: unchanged fields and creation timestamp are preserved;
   explicitly clearing optional fields persists the cleared values.
3. Mark complete and incomplete, including repeated assignments: exact desired
   state is returned and persisted.
4. Delete a task: it disappears from list and detail returns 404.
5. Restart the application: creations, edits, status changes, and deletions remain.
6. Submit blank/oversized titles, invalid/leap dates, invalid types, or immutable
   fields: actionable validation errors occur without partial persistence.
7. Filter around yesterday/today/tomorrow with a fixed clock: exact documented
   membership is returned, including completed and undated exclusions.
8. Sort in both directions: title casing, equal values, and missing dates follow
   the ordering contract.
9. Complete the CRUD journey through the UI using visible, labelled controls.
   Show loading, empty-list, no-matches, and retryable failure states. Preserve
   form input on failure. Prevent duplicate submits. Confirm deletion and allow
   cancellation. Provide keyboard focus and responsive mobile layout.
10. Run the packaged app with persistent mounted storage: health, CRUD, and
    persistence survive a container restart.

## Quality boundaries

This is a single-user local application without authentication. Production
internet hosting is outside the assignment. Database access uses parameterized
SQL and transactions. Tests use isolated storage and a controllable clock.
There is no runtime seed data. Documentation states limitations and exact
verification performed, including any unavailable tooling.
